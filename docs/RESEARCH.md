## 2. Что мы изменили в исходном ТЗ (и почему)

| Было в ТЗ | Стало | Уверенность | Основание |
|---|---|---|---|
| ОАК 10 дней, ЭКГ 14 дней, коагулограмма обязательна | **ОАК и ЭКГ ≤ 30 дней** на дату процедуры; коагулограмма только по назначению врача (при антикоагулянтах или нарушении свёртываемости) | [Certain] | S2 |
| Аллергопроба обязательна, с загрузкой файла | вопрос «аллергия на лекарства / реакции на наркоз» в анкете; аллергопроба только если её назначил врач | [Likely] | в памятке колоноскопии её нет (разбор судьи) |
| SPLIT по умолчанию | **схему и препарат выбирает врач** при допуске; до этого таймлайн не строится | [Certain] | памятка S1: при наркозе схема может быть одноэтапной |
| «закончить жидкость за 4 ч» | параметр `liquid_stop_hours`, **по умолчанию 2 ч**, врач меняет в пределах 2–4 ч; жидкость не останавливается раньше конца второй дозы | [Certain] | S4 (≥2 ч), S1 (2–4 ч) |
| APScheduler + машина времени | один `tick` раз в минуту (pg_cron → Vercel) выбирает события `due_at ≤ now + offset`; **виртуальное время на каждый визит отдельно** | [Certain] | serverless: фоновых процессов нет; перемотка не ломает других пациентов |
| red flags по словам («кровь») | фразы + исключения («анализ крови», «сдать кровь») + набор безобидных вопросов в тестах | [Certain] | разбор судьи |
| Объяснения заключения нет | словарь терминов заключения + детерминированный уровень тревоги + AI-пересказ + запись к специалисту | [Certain] | требование кейса |
| Запоры: событие за 7 дней | диета начинается **за 5 дней** вместо 3 | [Likely] | S2: «диета 3–5 дней» |
| FAQ о продукте до начала диеты: «разрешены только…» | «сейчас ограничений нет, диета начнётся {дата}» | [Certain] | логика фаз |
| Python/aiogram/SQLite | TypeScript: Next.js + grammY + Supabase Postgres (всё open source); деплой на Vercel | [Certain] | требование команды к Vercel и Supabase |

## 3. Входные данные и переменные

### 3.1 От пациента (бот или сайт)
| Переменная | Тип | Проверки |
|---|---|---|
| `lang` | ru / kk | выбор на первом экране |
| `consent` | bool | без согласия дальше нельзя |
| `name`, `phone` | строка | синтетические в демо |
| `scheduled_at` | дата + слот | не в прошлом; не воскресенье; Пн–Пт 8–20, Сб 9–17; слоты 08:00–13:30 поддержаны памяткой, после 14:00 → `NEEDS_CLINIC_REVIEW` |
| `screening[code]` | YES / NO / UNKNOWN | 14 вопросов, пропустить нельзя, UNKNOWN ≠ NO |
| `tests[code]` | {done, date} | дата не в будущем, не старше 1 года; действует на **дату процедуры** |
| `stool_check` | 1–4 | цветная шкала |
| `checklist[item]` | yes / no | критичные пункты с «нет» → `PREP_PROBLEM` |
| `feedback` | clarity 1–5, completed yes/partly/no, текст | после процедуры |
| свободный текст | строка | сначала red flags, потом FAQ |

### 3.2 От врача (панель или PDF)
| Переменная | Значения |
|---|---|
| `clearance` | CLEARED / NOT_CLEARED / CONSULT |
| `prep_drug` | Эзиклен / Кленсия / Фортранс |
| `prep_scheme` | SPLIT / SINGLE_EVENING |
| `liquid_stop_hours` | 2–4 |
| `labs[]` | показатель, значение, ед., референс, отметка |
| `conclusions[]`, `instructions[]` | текст врача дословно |
| `report_text` | заключение колоноскопии (после процедуры) |

### 3.3 Вычисляемые
`flags[]` (severity URGENT/HIGH/MEDIUM, assignee DOCTOR/COORDINATOR), `status`, `timeline[]`, `diet_phase(now)`, `report_terms[]`, `report_alarm_level (0/1/2)`, метрики.

## 4. Пользовательский путь

### До процедуры
1. **Запись**: язык → согласие → услуга «Колоноскопия с седацией» → дата и слот.
2. **Анкета противопоказаний** (кнопки Да / Нет / Не знаю): антикоагулянты и антиагреганты (список названий), диабет и сахароснижающие, GLP-1 (семаглутид и др.), препараты железа, осложнения наркоза, аллергия на лекарства, сердце, лёгкие, свёртываемость, беременность, **острые симптомы сейчас** (→ URGENT), запоры (→ диета 5 дней), кардиостимулятор или имплантированные устройства, сопровождающий.
3. **Сводка** «Проверьте ответы» → подтвердить.
4. **Анализы**: ОАК и ЭКГ (≤30 дней на дату процедуры). Нет или истекут → «сдайте до {дата}».
5. **Итог**: флаги → «обсудите с врачом» + заявка в панели; всё чисто → «ждём проверки врача».
6. **Врач** проверяет, при желании загружает PDF (анализы, заключения, указания), выбирает препарат, схему и окно голода → «Опубликовать» (допущен / не допущен / нужна консультация).
7. **План подготовки** строится от слота и схемы. Напоминания: начало диеты (D-3 или D-5), D-2, **D-1 напоминание о визите** + бульон до 14:00, 14:00 только прозрачные жидкости, доза 1 (подтвердить), оценка стула вечером, доза 2 (подтвердить), оценка стула утром (итог), стоп жидкости, **утренний чек-лист**, «пора выезжать» с адресом.
8. Не подтвердил дозу → повтор через 60 мин → ещё 60 мин → флаг HIGH.
9. Утром стул не 4 или критичный пункт «нет» → `PREP_PROBLEM`: «свяжитесь с клиникой ДО выезда» (метрика «нарушения подготовки», предотвращённая отмена на месте).
10. В любой момент: FAQ, «можно ли X?» по фазе диеты, red flags, «Отменить или перенести визит» (метрика отмен с причиной).

### После процедуры
11. Врач отмечает «Процедура проведена» → бот: памятка «что нормально, а что тревожно» (S9) + короткий отзыв.
12. Врач вносит **заключение колоноскопии** → система подсвечивает термины, считает уровень тревоги по словарю (детерминированно, с учётом отрицаний «полипов не выявлено»), AI пишет пересказ простым языком только на основе словаря → врач видит превью → «Опубликовать».
13. Пациент получает нейтральное уведомление → защищённая страница: заключение дословно + термины + пересказ + оговорка «интерпретирует врач».
14. Уровень тревоги 2 (образование, стеноз, подозрение на злокачественный процесс, неполный осмотр) → кнопка **«Записаться к специалисту»** (гастроэнтеролог или колопроктолог) → заявка с приоритетом в панели (метрика конверсии в консультацию). Уровень 1 (полип удалён, биопсия, гистология ожидается) → «обсудите на приёме» + кнопка записи.

## 5. Метрики кейса, как их считает система
| Метрика | Как считаем в MVP | Как доказать эффект в пилоте |
|---|---|---|
| Отмены | визиты `CANCELLED` + причина; `PREP_PROBLEM`, выявленные до выезда | сравнение доли отмен до и после пилота |
| Нарушения подготовки | неподтверждённые дозы, стул ≠ 4 утром, «нет» в чек-листе | Бостонская шкала (BBPS) в заключении: доля ≥ 6 (цель ≥ 90%, S5) |
| Повторные звонки | доля вопросов, закрытых FAQ без эскалации, и число заявок HELP / FAQ_UNANSWERED | журнал колл-центра |
| Конверсия в консультацию | записи SPECIALIST / число заключений с тревогой ≥ 1 | данные МИС |

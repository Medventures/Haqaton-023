Трек Green Clinic, задача 3: подготовка к исследованию. MVP-маршрут — колоноскопия с седацией.

## Проблема

Перед колоноскопией пациенту нужно проверить противопоказания, сдать анализы и строго выполнить подготовку кишечника. Неадекватная подготовка встречается у 10–25% пациентов и даёт 12–22% избыточных затрат из-за повторных исследований. Ошибки приводят к отменам в день процедуры и повторным звонкам в клинику. После исследования пациент получает заключение с терминами («образование», «биопсия», «полипэктомия») и без врача не понимает, что с этим делать.

## Решение

Telegram-бот и веб-сервис ведут пациента по всей цепочке кейса:

1. **Противопоказания и анализы.** Анкета из 15 вопросов кнопками «Да / Нет / Не знаю». «Не знаю» всегда даёт флаг врачу и никогда не приравнивается к «нет». Для антикоагулянтов показывается список названий препаратов. ОАК и ЭКГ проверяются на срок годности (30 дней) **на дату процедуры**. Если анализ истечёт, бот говорит, в какой период пересдать.
2. **Решение врача.** Врач загружает PDF (анализы, заключения, указания, допуск) или заполняет форму, видит превью и публикует. Препарат (Эзиклен / Кленсия / Фортранс) и схему выбирает только врач.
3. **План подготовки и напоминания** строго по памятке клиники:
   - бесшлаковая диета за 3 дня (5 дней при запорах);
   - накануне до 14:00 только бульон, после 14:00 только прозрачные жидкости;
   - две дозы препарата с подтверждением «Выпил(а)», без подтверждения — повтор и флаг врачу;
   - оценка стула по цветной шкале;
   - окно голода;
   - утренний чек-лист и напоминание «пора выезжать» с адресом.
4. **Объяснение заключения.**
   - Текст врача показывается дословно, термины подсвечены и объяснены по словарю.
   - AI даёт пересказ простыми словами с оговоркой «интерпретирует врач».
   - Уровень тревоги считают правила с учётом отрицаний («полипов не выявлено»).
5. **Запись к специалисту** при тревожных формулировках: гастроэнтеролог или колопроктолог, выбор слота, заявка с приоритетом в панели врача.

**Безопасность:**
- Бот не ставит диагноз, не отменяет лекарства и не решает о допуске.
- Тревожные фразы («кровь в стуле», «сильная боль») прерывают любой сценарий: срочный ответ и флаг URGENT. Безобидные фразы вроде «анализ крови» тревогу не вызывают.
- Анализы и заключения доступны только на странице по подписанной ссылке. В Telegram приходят нейтральные уведомления.

**Метрики кейса на дашборде врача:** отмены и их причины, нарушения подготовки до выезда, доля вопросов, закрытых без звонка, конверсия в консультацию специалиста, понятность подготовки по отзывам.

## Демо

- Сайт: https://medhubhackathon.vercel.app
- Telegram-бот: [@medadvisergreenbot](https://t.me/medadvisergreenbot)
- Панель врача: https://medhubhackathon.vercel.app/doctor (пароль выдаётся жюри отдельно)

Сценарий показа:
1. `/start` в боте, ответить «Да» на антикоагулянты → флаг врачу.
2. Написать «у меня кровь в стуле» → срочный ответ.
3. Панель врача → «＋ Демо-пациенты»: 7 готовых сценариев.
4. Опубликовать допуск → появляется план из 16 событий.
5. **Машина времени** (сдвигает время только у выбранного пациента) → напоминания, эскалация неподтверждённой дозы, шкала стула, чек-лист.
6. «Демо 7» → заключение с тревожной формулировкой, пересказ и запись к специалисту.

Команды бота: `/start`, `/status`, `/plan`, `/ask`, `/contact`, `/lang` (русский / казахский), `/cancel`, `/help`.

## Запуск

Требования: Node.js 20+, проект Supabase (Postgres), Telegram-бот от @BotFather.

```bash
npm install
cp .env.example .env.local    # заполнить значения
npm test                      # 60 тестов правил и сценариев
npm run dev                   # http://localhost:3000
```

База данных:
1. Применить `supabase/migrations/0001_init.sql` и `0002_cron.sql`.
2. Выполнить `insert into private.config(key, value) values ('app_secret', '<APP_DB_SECRET>'), ('tick_url', 'https://<домен>/api/cron/tick'), ('cron_secret', '<CRON_SECRET>');`

Деплой (Vercel):
1. Импортировать репозиторий и задать переменные окружения.
2. Открыть `https://<домен>/api/setup?secret=<CRON_SECRET>`: регистрирует webhook и команды бота.

Переменные окружения (значения — в `.env.example`, без секретов):

| Переменная | Назначение |
|---|---|
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` | бот и проверка подписи webhook |
| `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `APP_DB_SECRET` | доступ к БД; все таблицы под RLS, пропускается только сервер с секретом |
| `SIGNING_SECRET` | подпись ссылок на страницу пациента |
| `CRON_SECRET` | `/api/cron/tick`, `/api/setup`, `/api/admin` |
| `DOCTOR_PASSWORD` | вход в панель врача |
| `APP_URL` | публичный адрес для ссылок из бота |
| `LLM_PROVIDER` | `anthropic`, `openai` (любой OpenAI-совместимый сервер, например Ollama с open-source моделью) или `none` |
| `ANTHROPIC_API_KEY`, `LLM_MODEL`, `OPENAI_BASE_URL` | настройки LLM |
| `CLINIC_PHONE`, `CLINIC_WHATSAPP` | контакты (в демо — демо-номер) |

## Структура проекта

```

lib/content/              контент для медиков: анкета, анализы, диета, план, FAQ, тревожные фразы,
                          словарь терминов заключения. Русский и казахский, у каждой записи указан источник

                          тревожные фразы, анализ заключения
lib/faq/                  нечёткий поиск по FAQ + выбор ответа через LLM
lib/ai/                   адаптер LLM и объяснение заключения с фильтром запрещённых фраз
lib/bot/                  Telegram-бот (grammY)
lib/flow.ts               оркестрация: статусы, флаги, план, отправка напоминаний, отчёт, запись
lib/pdf/                  разбор PDF врача (unpdf)
supabase/migrations/      схема БД, RLS, pg_cron
tests/                    Vitest: сценарии ТЗ, red flags, отрицания, PDF
docs/RESEARCH.md          ресерч: входные данные, переменные, пользовательский путь, источники
docs/superpowers/plans/   план разработки, сильные и слабые стороны
```

Стек (open source): TypeScript, Next.js 15, React 19, Tailwind CSS 4, grammY, Supabase Postgres (pg_cron, pg_net), unpdf, Vitest.

## Что готово

**Реализовано:**
- полная цепочка кейса в боте и на сайте, одна логика и одна БД;
- панель врача: список с сортировкой URGENT сверху, карточка, флаги с исполнителем (врач или координатор), заявки, разбор PDF, публикация, «процедура проведена», заключение с AI-пересказом, машина времени, демо-сид и сброс, дашборд метрик;
- напоминания через pg_cron раз в минуту, идемпотентность апдейтов Telegram и кнопок;
- интерфейс на русском и казахском.

**Известные ограничения:**
- Тексты памятки взяты из открытых страниц primegc.kz. Записи с пометкой `TODO_MEDICAL_REVIEW` и казахские медицинские формулировки требуют проверки врачом.
- LLM в демо — Claude (не open source). Он спрятан за адаптером и заменяется локальной моделью (`LLM_PROVIDER=openai` + Ollama) или отключается (`LLM_PROVIDER=none`). Без LLM всё работает на правилах.
- Защита панели врача — один пароль (уровень демо). Нет интеграции с МИС и расписанием. WhatsApp — следующий этап.
- Все данные синтетические.
